# Dashboard Feature Documentation

## Overview

The HealthAI+ Dashboard provides real-time operational metrics for healthcare facilities. It displays key performance indicators (KPIs) across revenue, patients, appointments, encounters, and invoices domains.

## Dashboard Components

The page (`frontend/src/app/[locale]/(dashboard)/dashboard/page.tsx`) follows
prrapp's dashboard board: a **Today** header, then worklist tiles grouped by
area, then the forecast. Components live in
`frontend/src/modules/reporting/components/dashboard/`.

### Today header

The date, and a count of tiles whose tone asks for action (amber, orange or
red) — or "every list is clear". A Refresh button forces a cache refresh.

### Worklist tiles (`dashboard-board.tsx`)

Each tile is one figure, coloured by what it asks of the reader (green when
clear, its list's own tone while something waits, red when overdue or urgent)
and links to the page that works it.

| Group | Tiles |
|---|---|
| Clinics | Appointments today, Patients in clinic, No-shows & cancellations, Booked next 7 days, New patients this month |
| Wards & diagnostics | Inpatients, Discharges due, Open lab orders (urgent count in the note), Open imaging orders, Lab reports to sign off |
| Revenue cycle | Billed this month, Unpaid invoices, Overdue > 30 days, Receivables 90+ days, Collected (90 days) |

A tile shows `—` when the cache predates the field (see *Backwards
compatibility*).

### AI forecast & insights (`dashboard-forecast.tsx`)

- **Projection cards**: billing by month end, encounters over the next 7
  days, and new patients by month end, each with an ≈80% range and the change
  against last month / the last 7 days.
- **Trend chart**: the last 6 weeks as bars and the next 2 weeks as a dashed
  forecast line with its band, switchable between Encounters, Billing and New
  patients.
- **What needs attention**: up to five insights ranked critical → watch →
  on track → note, built by `buildDashboardInsights`
  (`frontend/src/modules/reporting/lib/dashboard-insights.ts`, tested beside
  it). Each sentence is read off a figure on the page; none is generated by an
  LLM.
- **Receivables by age**: open balance split 0–30 / 31–60 / 61–90 / 90+ days
  past due, with the 90-day collection rate.

### Forecast model

`backend/services/ai-gateway/src/modules/report-builder/services/dashboard-forecast.ts`
fits each daily series on history through yesterday (today is partial):

1. A day-of-week index from the last 8 weeks (a quiet Sunday stays quiet).
2. Holt double exponential smoothing on the deseasonalised series for level
   and trend. The smoothing weights (α ∈ {0.1, 0.2, 0.3, 0.5},
   β ∈ {0.05, 0.15}) are the pair with the lowest one-step-ahead error on the
   series' own history, so lumpy billing is smoothed harder than steady visits.
3. Projection = (level + damped trend) × day-of-week index, clamped at 0. The
   trend is damped by φ = 0.9 per day so it does not run away over a month.
4. Band = ±1.28σ of the one-step-ahead errors over the last 4 weeks, widening
   with the horizon. A total over several days (month end, next 7 days)
   combines the daily spreads in quadrature rather than adding each day's
   low and high.

The horizon is 14 days, extended to reach month end. A series with activity
on fewer than 6 of the last 28 days is not forecast (`null`); the UI then says
there is not enough history rather than drawing a guess. Month-end projection
= month-to-date actual + the forecast for the remaining days.

## Data Sources

The dashboard aggregates data from two primary databases:

### Clinical Database
- Patient registration data
- Appointment schedules and status
- Encounter records

### RCM Database
- Invoice data
- Payment status
- Due date information

## Metrics Reference

### Revenue Metrics

| Metric | Description | Update Frequency |
|--------|-------------|------------------|
| Revenue MTD | Total net invoice amount for current month (excluding cancelled) | 30 min cache |
| Revenue Last Month | Total net invoice amount for previous month | 30 min cache |
| Revenue Growth | Percentage change from last month | Calculated |

### Patient Metrics

| Metric | Description | Update Frequency |
|--------|-------------|------------------|
| Total Patients | Count of all registered patients | 30 min cache |
| New Patients (Month) | Patients registered in current month | 30 min cache |
| Patient Growth | New patients as percentage of total | Calculated |

### Appointment Metrics

| Metric | Description | Update Frequency |
|--------|-------------|------------------|
| Appointments Today | All appointments scheduled for today | 30 min cache |
| Completed Today | Appointments with status 'completed' | 30 min cache |
| Cancelled Today | Appointments with status 'cancelled' | 30 min cache |
| No-Show Today | Appointments with status 'no_show' | 30 min cache |
| Completion Rate | Completed / Total today | Calculated |

### Encounter Metrics

| Metric | Description | Update Frequency |
|--------|-------------|------------------|
| Encounters Today | Encounters created today | 30 min cache |
| Encounters This Week | Encounters in current week | 30 min cache |
| Utilization Rate | Encounters / Expected capacity | Calculated |

### Invoice Metrics

| Metric | Description | Update Frequency |
|--------|-------------|------------------|
| Unpaid Invoices | Count of invoices with status 'unpaid' or 'partial' | 30 min cache |
| Unpaid Amount | Total balance due on unpaid invoices | 30 min cache |
| Overdue Invoices | Unpaid invoices with due_date > 30 days ago | 30 min cache |
| Overdue Amount | Total balance on overdue invoices | 30 min cache |

### Worklist, history and forecast fields

| Field | Source | Definition |
|---|---|---|
| `worklists.encountersInProgress` | clinical `encounters` | status `in-progress`, `arrived`, `triaged`, excluding inpatient (`IMP`) encounters |
| `worklists.ordersOpen` / `labOrdersOpen` / `imagingOrdersOpen` | clinical `clinical_orders` | status `ordered` or `in_progress` (by `order_type`) |
| `worklists.urgentOrdersOpen` | clinical `clinical_orders` | open, priority `stat`/`urgent`/`asap`/`emergency` |
| `worklists.labReportsAwaitingSignOff` | clinical `lab_reports` | `report_status` `DRAFT` or `PRELIMINARY` |
| `worklists.inpatientsCurrent` | clinical `inpatient_admissions` | `ADMITTED`, `ACTIVE`, `ON_LEAVE`, `DISCHARGE_PLANNING` |
| `worklists.dischargesDue` | clinical `inpatient_admissions` | current, and `DISCHARGE_PLANNING` or `expected_discharge_date` ≤ today |
| `worklists.appointmentsNext7Days` | clinical `appointments` | from now to 7 days ahead, not cancelled/no-show |
| `trends` | clinical `encounters` (`COALESCE(start_time, created_at)`), `patients.created_at`; rcm `invoices.invoice_date` | 91 daily values ending today |
| `forecast` | computed from `trends` | see *Forecast model* |
| `arAging` | rcm `invoices` | `unpaid`/`partial` with `balance_due > 0`, bucketed by days past `due_date` (no due date counts as current); collection rate = paid ÷ billed for invoices raised in the last 90 days |

Each of `worklists`, `trends`/`forecast` and `arAging` is fetched
independently: a failing query logs an error and leaves that part out instead
of failing the endpoint. All queries filter by `tenant_id`.

## Caching Architecture

The dashboard uses Redis caching to optimize performance:

### Cache Strategy

1. **Initial Load:** First request fetches from database and caches
2. **Subsequent Loads:** Serve from Redis cache (~50-100ms)
3. **Background Refresh:** Scheduled job warms cache every 30 minutes
4. **Manual Refresh:** Users can trigger refresh via UI button

### Cache Configuration

Configure via environment variables in AI Gateway service:

```bash
# Redis connection
REDIS_URL=redis://localhost:6379

# Cache duration (minutes)
DASHBOARD_CACHE_TTL_MINUTES=30

# Enable/disable background warming
DASHBOARD_CACHE_WARMING_ENABLED=true
```

### Cache Key Format

```
dashboard:metrics:{tenantId}:{currency}
```

Each tenant has separate cached metrics, scoped by currency.

## Frontend Integration

### Using the Hook

```typescript
import { useDashboardMetrics } from '@/modules/reporting/hooks/use-dashboard-metrics';

function Dashboard() {
  const { data: currency } = useResolveConfig('finance.currency');
  const { data, isLoading, refetch } = useDashboardMetrics(currency ?? 'INR');

  if (isLoading) {
    return <DashboardSkeleton />;
  }

  return (
    <div>
      <MetricCard
        title="Revenue MTD"
        value={formatCurrency(data.revenueMTD, currency)}
        trend={data.revenueGrowth}
      />
      {/* ... other metrics */}
    </div>
  );
}
```

### Available Data

The `useDashboardMetrics` hook returns:

```typescript
{
  data: DashboardMetrics;      // All metrics
  isLoading: boolean;          // Loading state
  isError: boolean;            // Error state
  isFetching: boolean;         // Background refetch
  fromCache: boolean;          // Whether data came from cache
  ttlSeconds: number;          // Remaining cache TTL
  refetch: () => Promise<void>; // Force refresh
}
```

## Demo data

Local and demo databases have little day-to-day activity, so the forecast would
show "not enough history". `seed/clinical/27-demo-activity.sql` and
`seed/rcm/09-demo-invoices.sql` (both in `seed/run-seeds.sh`) generate 90 days
for tenant `11111111-…` at Zeal Main Hospital: ~240 patients, ~1,900
appointments with a weekly rhythm and slight growth, today's clinic part-way
through, next week's bookings, open lab/imaging orders and reports awaiting
sign-off, ~2 admissions a day with a few discharges due, and invoices with a
payment mix that ages receivables into every bucket. They are deterministic,
replace only their own rows, and are dated relative to the day they run — re-run
them before a demo (see the GCP demo runbook). Demo invoices are header-only
(no lines).

## Numeric metrics

`SUM()` over a `numeric` column comes back from Prisma as a `Decimal`, which
serialises as a string. Every metric value is converted with `Number()` before
it is cached; before this, `revenueMTD`, `unpaidAmount` and the other amount
metrics were cached as strings.

## Backwards compatibility

`worklists`, `trends`, `forecast` and `arAging` are optional in the response
type. A Redis entry written by an older ai-gateway lacks them until it expires
(default 30 minutes) or is refreshed; the page then shows `—` tiles and
"Projections appear once the metrics cache next refreshes".

## Currency Support

The dashboard supports multi-currency display:

1. Currency is resolved from tenant configuration (`finance.currency`)
2. Passed to the metrics endpoint as query parameter
3. Cached separately per currency per tenant

Supported currencies depend on tenant configuration.

## Troubleshooting

### Metrics Not Loading

1. Check AI Gateway service is running on port 3015
2. Verify Redis is running: `docker-compose up -d redis`
3. Check browser console for API errors
4. Verify tenant headers are being sent

### Stale Data

1. Click the refresh button to force cache update
2. Check Redis connection: `redis-cli PING`
3. Verify cache warming job is running in logs

### Cache Not Working

1. Check `REDIS_URL` is configured in `.env.local`
2. Verify Redis is accessible from AI Gateway
3. Check logs for "Redis not available" warnings
